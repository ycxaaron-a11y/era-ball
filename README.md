# ERA FC
世界杯 / 欧洲冠军杯与欧冠跨年代足球选秀网站。零 npm 运行依赖，可直接部署到静态网站服务。

## 运行
需要 Node.js（测试）和 Python 3（本地 HTTP 服务）。
```sh
cd /workspace/era-ball
npm test
npm run dev
```
将运行机器的 3000 端口转发到浏览器。不要通过 `file://` 打开 ES modules。
部署时保留完整项目文件，尤其是 `catalog-world-cup.js`、`catalog-ucl.js`、`multiplayer.js` 和 `config.js`，不能只上传 HTML。

## 当前玩法
- 12 个年代区间：1960–1969，以及从 1970 到 2024 的各五年区间。
- 48 支精选年代球队（世界杯 24、欧冠/欧洲冠军杯 24），990 条球员年代记录。
- 11 首发 + 5 替补，7 种阵型（新增带前腰的 4-2-3-1、4-3-1-2、3-4-1-2），3 次额外重转。每轮手动点击 Spin，球队与年代快速切换并停定后才显示候选；确认选人后等待下一次 Spin。
- 赛前确定征战年代、可选排除来源年代（Lock）。至少保留一个年代，开局后设置锁定。
- 先等概率抽一个未排除的年代，再抽该年代的一支球队；所有可用组合都有实际名单。
- 多个自然位置全部满额适配，其他位置扣 4/12 分，门将错位扣 45 分。
- 年代调整默认不扣分，仅选定战术角色扣 1–3 分。范戴克在各年代无额外扣分。
- 每支**来源球队**最多 3 名 S/S+，玩家跨来源组成的球队不受此上限限制。部分来源球队最高仅 A。
- S+ 每 1.8 秒循环分叉锯齿闪电与短促震动，确认入队时播放一次压落、冲击环与白雾；S 静态荧光紫、A 金、B 亮蓝、C 绿、D 深橙。候选卡和入队卡一致；支持减少动态效果偏好。
- 先点击候选球员，再点空位显示半透明试位与实际能力；再点同一位置才确认入队。换一个空位会重新等待确认，取消或刷新不会保存预览。
- 全部球员显示中文姓名，所有位置改为中文。候选卡只显示姓名、身高、位置及评级，不显示基础或适配能力数字。
- 453 个球员身份保留资料身高，其余按位置给出稳定的游戏设定值；按用户要求，界面统一显示厘米数字，内部保留 `heightEstimated` 区分资料与补全值，身高目前不额外改变评分。详见 [身高与中文资料说明](docs/player-metadata.md)。
- 点击已入队球员仍可查看基础值、位置扣分、年代扣分与最终能力，也可交换位置或移除。

评级是编辑估值，不是官方评分；名单是精选历史球员，不宣称全部注册名单均完整、逐项核验。跨年代表现没有可验证的真实对照。
[研究来源及规则边界](docs/era-research.md)记录了实际读取的比赛位置证据，以及哪些调整属于主观游戏平衡。
头像统一使用原创黑色人物剪影，暂不接入未经核验的真人照片。

## 已有网站如何更新
本仓库的 `main` 已连接 Netlify：正常推送代码后，由 Netlify 自动构建并更新同一个网址。
`netlify.toml` 已指定发布根目录 `.`，Build command 留空，不需要设置服务器或新增环境变量。
本次 v4 赛季升级在原 Supabase 项目执行一次 [合并升级 SQL](supabase/upgrade-all-v4.sql)，已经包含上次 Spin / 抢选锁 / 羁绊升级。上次执行过也可安全重跑，无需重建项目、仓库或网站。网页检测到缺少赛季接口时提供“复制升级 SQL”按钮。详细步骤见 [升级操作说明](docs/upgrade-v4.md)。
新版使用独立的 `era-fc-v2` 浏览器存档；旧版存档不会删除，但不会导入新选秀。更新后双方刷新网页并创建新房间。

## 新项目首次配置联机
1. 在自己的 Supabase SQL Editor 先执行 `supabase/multiplayer.sql`，再执行 `supabase/upgrade-all-v4.sql`（新增 `fc_*` 表，不覆盖旧的 `teams/players` 表）。
2. Authentication > Providers 中开启 Anonymous Sign-Ins。
3. `config.js` 仅存放可公开的项目地址与 publishable/anon key；也可在网页联机面板展开连接设置。不要填 service_role 或 secret key。
4. 房主先锁定赛前设置，然后创建房间。另一台设备或独立浏览器通过房间码加入，自动采用房主的赛事模式、征战年代和排除年代。
5. 双方独立选满 16 人后阵容锁定，进入同一届杯赛。服务器固定一次赛季随机种子并保存共同轮次；客户端依据相同种子和服务端校验后的阵容计算比赛，双方获得相同赛程和赛果。每 1.5 秒 HTTP 轮询同步，无需开启 Realtime publication。

联机与本地都计算位置、年代和羁绊后的首发能力。13 组历史搭档同时入队（含替补）后双方各 +2，多组叠加每人最多 +3、总能力最多 100；达到阈值会更新评级与边框。资料证据与游戏规则详见 [羁绊研究记录](docs/chemistry-research.md)。

新版服务器使用独立球员目录重算能力，不信任客户端提交的分数。按“来源球队 + 确切年份 + 球员”原子锁定版本，同一版本只能被一人持有；不同球队或年份的同一球员可由对手选择。自己的阵容仍不能重复同一球员身份。移除后释放版本锁。预览不提交，服务器确认成功后才入队、播放 S+ 落位效果。版本冲突回滚，网络重试使用同一请求标识，避免重复提交。

当前仍是朋友间原型：随机 Spin 在浏览器执行，尚未实现服务端权威随机或防篡改重转次数；已验证成员限制、原子版本锁、阵容修订号、权威能力计算与共同赛果。暂不支持释放离开者名额、房间自动清理或替补自动换人。新局请新建房间。

## 验证
`npm test` 验证数据年代覆盖、评分上限、多位置、年代模型、Lock/重转/重复选人、存档恢复与联机能力序列化等规则。
浏览器另检查了赛前设置、16 人选秀、位置交换、阵型与存档、赛季、手机布局和减少动态效果。
新增 `npm run build:database` 根据目录生成升级 SQL。可选数据库集成检查：安装 PGlite 后设置 `ERA_PGLITE_MODULE` 为其模块绝对路径，运行 `npm run test:database`。浏览器与本地 PostgreSQL 联合验证包括双人抢同版本、跨年代同身份、完整 16 人及共同决赛。真实 Supabase v3 验证需先执行升级 SQL；本地验证不代表托管数据库已升级。

可选浏览器检查：先启动 3000 端口服务，设置 `ERA_PLAYWRIGHT_MODULE`（Playwright 模块路径）及 `ERA_PGLITE_MODULE`，执行 `node tests/browser-protocol.mjs`；可用 `ERA_CHROMIUM` 指定 Chromium。测试把请求接到本地 PostgreSQL 测试库，不访问托管数据库。

## v4 逐轮赛季

入口“进入冠军赛季”打开独立页面 `#season`，返回阵容后可继续。世界杯和欧冠均采用自定义 16 队杯赛：四组四队，单循环三轮、小组前二晋级、四分之一决赛、半决赛、决赛，淘汰赛单场决胜。不是特定历史年份的官方赛程，不含季前赛或主客场两回合。

每轮公布全体比赛比分，点击战报展开进球分钟、进球者、助攻者、全场 MVP 与双方 MVP。积分榜、射手榜、助攻榜、MVP 次数及场均表现只统计已经揭晓的比赛；最终展示冠军、赛季 MVP、金靴及助攻王。淘汰赛平局以点球决胜，点球大战不计入射手榜。积分同分按净胜球、进球数、固定签位排序。个人表现与评分属于游戏模拟，替补暂不自动上场。

联机房主在 A 组上半区，客队在 C 组下半区，双方晋级才可能在决赛相遇；提前出局仍可继续观赛。任何一方推进均同步给对方；同一轮同时点击由服务器行锁及期望轮次合并，不会跳两轮。服务器保存种子和进度，赛果在浏览器用固定算法重现，尚非完整的服务端赛事引擎。单人赛季保存在当前浏览器；联机赛季在当前标签页刷新后通过房间身份恢复。

验证：`npm test` 包含 40 个固定种子下的分区、轮次、赛果一致性及进球统计校验；`npm run test:database` 验证合并 SQL、成员权限、共享种子、轮次并发、完成上限、重复升级不丢进度。可选 `node tests/browser-season.mjs`（同浏览器依赖环境变量）验证手机完整六轮、战报和存档，以及双浏览器同步、重复点击与刷新恢复。

## v4.1 分阶段观看与快捷模拟

赛季页面每次只显示当前阶段的一轮对阵，可切换已解锁的小组赛、四分之一决赛、半决赛和决赛。小组积分与个人榜折叠展示；结局明确显示每个人类球队夺冠或在哪一轮出局。

“自动模拟至决赛”每 300 毫秒揭晓一场比分，跨轮推进到决赛前（已完成五轮）停止，决赛必须手动开始。可中途停止；单人模式另有 “Skip to end · 直接看结局”，一次跳到赛季终局。联机没有此跳过按钮，仍使用现有共享种子与逐轮 RPC，不需要新增 SQL。浏览器每场 300 毫秒为揭晓间隔，网络及渲染可能增加轮次切换时间。

阵容卡的评级、边框及闪电使用位置、年代、羁绊结算后的最终能力；例如 99 分错位至 95 分显示 S 并取消闪电，94 分错位至 90 分显示 A 金色。试位、确认、位置交换和阵型改变均重新计算；替补无位置扣分。候选球员卡仍显示该版本的原始评级，尚未选择位置时不提前扣分。S+ 落位特效仅在入队位置最终评级确为 S+ 时触发。
