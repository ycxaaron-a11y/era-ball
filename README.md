# ERA FC
世界杯 / 欧洲冠军杯与欧冠跨年代足球选秀网站。零 npm 运行依赖，可直接部署到静态网站服务。

## 运行
需要 Node.js（测试）和 Python 3（本地 HTTP 服务）。
```sh
cd /workspace/era-ball
npm test
npm run dev
```
将运行机器的 3000 端口转发到浏览器。不要通过 `file://` 打开 ES modules。
部署时保留完整项目文件，尤其是 `catalog-world-cup.js`、`catalog-ucl.js`、`multiplayer.js` 和 `config.js`，不能只上传 HTML。

## 当前玩法
- 12 个年代区间：1960–1969，以及从 1970 到 2024 的各五年区间。
- 73 支精选年代球队（世界杯 37、欧冠/欧洲冠军杯 36），1550 条球员年代记录、1259 个不同球员身份。
- 11 首发 + 5 替补，6 种可选阵型（4-3-3、4-3-3 进攻型、4-4-2、4-2-4、4-2-3-1、4-3-1-2），3 次额外重转。每轮手动点击 Spin，球队与年代快速切换并停定后才显示候选；确认选人后等待下一次 Spin。
- 赛前确定征战年代、可选排除来源年代（Lock）。至少保留一个年代，开局后设置锁定。
- 先等概率抽一个未排除的年代，再抽该年代的一支球队；所有可用组合都有实际名单。
- 多个自然位置全部满额适配，其他位置扣 4/12 分，门将错位扣 45 分。
- 年代调整默认不扣分，仅选定战术角色扣 1–3 分。范戴克在各年代无额外扣分。
- 不再限制每支来源球队的 S/S+ 数量，按当届/当季表现分别估值。部分来源球队最高仅 A；当前 44 个 S+ 版本，占全部记录约 2.8%。
- S+ 每 1.8 秒循环分叉锯齿闪电与短促震动，确认入队时播放一次压落、冲击环与白雾；S 静态荧光紫、A 金、B 亮蓝、C 绿、D 深橙。候选卡和入队卡一致；支持减少动态效果偏好。
- 先点击候选球员，再点空位显示半透明试位与实际能力；再点同一位置才确认入队。换一个空位会重新等待确认，取消或刷新不会保存预览。
- 全部球员显示中文姓名，所有位置改为中文。候选卡显示姓名、身高、位置、原始评级及“初始能力”数字；阵容内显示位置、年代、羁绊调整后的实际能力。
- 807 个球员身份保留整理的身高值，其余按位置给出稳定的游戏设定值；按用户要求，界面统一显示厘米数字，内部保留 `heightEstimated` 区分资料与补全值，身高目前不额外改变评分。详见 [身高与中文资料说明](docs/player-metadata.md)。
- 点击已入队球员仍可查看基础值、位置扣分、年代扣分与最终能力，也可交换位置或移除。

评级是编辑估值，不是官方评分；名单是精选历史球员，不宣称全部注册名单均完整、逐项核验。跨年代表现没有可验证的真实对照。
[研究来源及规则边界](docs/era-research.md)记录了实际读取的比赛位置证据，以及哪些调整属于主观游戏平衡。
头像统一使用原创黑色人物剪影，暂不接入未经核验的真人照片。

## 已有网站如何更新
本仓库的 `main` 已连接 Netlify：正常推送代码后，由 Netlify 自动构建并更新同一个网址。
`netlify.toml` 已指定发布根目录 `.`，Build command 留空，不需要设置服务器或新增环境变量。
本次 v7 后场及三人羁绊升级在原 Supabase 项目执行一次 [完整安装及升级 SQL](supabase/setup-all.sql)，已经包含上次 Spin / 抢选锁 / 羁绊升级。上次执行过也可安全重跑，无需重建项目、仓库或网站。网页检测到缺少赛季接口时提供“复制升级 SQL”按钮。详细步骤见 [升级操作说明](docs/online-setup.md)。
新版使用独立的 `era-fc-v2` 浏览器存档；旧版存档不会删除，但不会导入新选秀。更新后双方刷新网页并创建新房间。

## 从未升级过的原项目如何开启联机

完整图文位置与操作次序见 [从零配置与历史升级合并说明](docs/online-setup.md)。只需在原 Supabase 项目执行一次 [`supabase/setup-all.sql`](supabase/setup-all.sql)，它已包含最初建表、版本锁、球员目录、羁绊、所有阵型、逐轮赛季和决赛直播。新旧项目均可执行，重复运行不删除房间或球员。无需逐份执行历史 SQL。

随后在 Authentication → Sign In / Providers 开启 Allow new users to sign up 和 Allow anonymous sign-ins，并保存。网站公开项目配置已经填好，保持不变。双方刷新同一个网站，房主创建房间，朋友用房间码加入。使用两台设备或独立浏览器身份。

联机与本地都计算位置、年代和羁绊后的首发能力。13 组双人历史搭档同时入队（含替补）后双方各 +2，双人加成每人最多 +3；另有三组仅首发激活的三人羁绊，BBC / MSN 各 +5、荷兰三剑客各 +5%，与双人加成取较高值，总能力最多 100；达到阈值会更新评级与边框。资料证据与游戏规则详见 [羁绊研究记录](docs/chemistry-research.md)。

新版服务器使用独立球员目录重算能力，不信任客户端提交的分数。按“来源球队 + 确切年份 + 球员”原子锁定版本，同一版本只能被一人持有；不同球队或年份的同一球员可由对手选择。自己的阵容仍不能重复同一球员身份。移除后释放版本锁。预览不提交，服务器确认成功后才入队、播放 S+ 落位效果。版本冲突回滚，网络重试使用同一请求标识，避免重复提交。

当前仍是朋友间原型：随机 Spin 在浏览器执行，尚未实现服务端权威随机或防篡改重转次数；已验证成员限制、原子版本锁、阵容修订号、权威能力计算与共同赛果。暂不支持释放离开者名额、房间自动清理或替补自动换人。新局请新建房间。

## 验证
`npm test` 验证数据年代覆盖、评分上限、多位置、年代模型、Lock/重转/重复选人、存档恢复与联机能力序列化等规则。
浏览器另检查了赛前设置、16 人选秀、位置交换、阵型与存档、赛季、手机布局和减少动态效果。
新增 `npm run build:database` 根据目录生成升级 SQL。可选数据库集成检查：安装 PGlite 后设置 `ERA_PGLITE_MODULE` 为其模块绝对路径，运行 `npm run test:database`。浏览器与本地 PostgreSQL 联合验证包括双人抢同版本、跨年代同身份、完整 16 人及共同决赛。真实 Supabase v3 验证需先执行升级 SQL；本地验证不代表托管数据库已升级。

可选浏览器检查：先启动 3000 端口服务，设置 `ERA_PLAYWRIGHT_MODULE`（Playwright 模块路径）及 `ERA_PGLITE_MODULE`，执行 `node tests/browser-protocol.mjs`；可用 `ERA_CHROMIUM` 指定 Chromium。测试把请求接到本地 PostgreSQL 测试库，不访问托管数据库。

## v4 逐轮赛季

入口“进入冠军赛季”打开独立页面 `#season`，返回阵容后可继续。世界杯和欧冠均采用自定义 16 队杯赛：四组四队，单循环三轮、小组前二晋级、四分之一决赛、半决赛、决赛，淘汰赛单场决胜。不是特定历史年份的官方赛程，不含季前赛或主客场两回合。

每轮公布全体比赛比分，点击战报展开进球分钟、进球者、助攻者、全场 MVP 与双方 MVP。积分榜、射手榜、助攻榜、MVP 次数及场均表现只统计已经揭晓的比赛；最终展示冠军、赛季 MVP、金靴及助攻王。淘汰赛平局以点球决胜，点球大战不计入射手榜。积分同分按净胜球、进球数、固定签位排序。个人表现与评分属于游戏模拟，替补暂不自动上场。

联机房主在 A 组上半区，客队在 C 组下半区，双方晋级才可能在决赛相遇；提前出局仍可继续观赛。任何一方推进均同步给对方；同一轮同时点击由服务器行锁及期望轮次合并，不会跳两轮。服务器保存种子和进度，赛果在浏览器用固定算法重现，尚非完整的服务端赛事引擎。单人赛季保存在当前浏览器；联机赛季在当前标签页刷新后通过房间身份恢复。

验证：`npm test` 包含 40 个固定种子下的分区、轮次、赛果一致性及进球统计校验；`npm run test:database` 验证合并 SQL、成员权限、共享种子、轮次并发、完成上限、重复升级不丢进度。可选 `node tests/browser-season.mjs`（同浏览器依赖环境变量）验证手机完整六轮、战报和存档，以及双浏览器同步、重复点击与刷新恢复。

## v4.1 分阶段观看与快捷模拟

赛季页面每次只显示当前阶段的一轮对阵，可切换已解锁的小组赛、四分之一决赛、半决赛和决赛。小组积分与个人榜折叠展示；结局明确显示每个人类球队夺冠或在哪一轮出局。

“自动模拟至决赛”每 300 毫秒揭晓一场比分，跨轮推进到决赛前（已完成五轮）停止，决赛必须手动开始。可中途停止；单人模式另有 “Skip to end · 直接看结局”，一次跳到赛季终局。联机没有此跳过按钮，仍使用现有共享种子与逐轮 RPC，不需要新增 SQL。浏览器每场 300 毫秒为揭晓间隔，网络及渲染可能增加轮次切换时间。

阵容卡的评级、边框及闪电使用位置、年代、羁绊结算后的最终能力；例如 99 分错位至 95 分显示 S 并取消闪电，94 分错位至 90 分显示 A 金色。试位、确认、位置交换和阵型改变均重新计算；替补无位置扣分。候选球员卡仍显示该版本的原始评级，尚未选择位置时不提前扣分。S+ 落位特效仅在入队位置最终评级确为 S+ 时触发。

## v5 决赛直播

评级门槛保持不变：S+ 99–100、S 94–98、A 88–93、B 82–87、C 75–81、D 1–74。

手动开始决赛后进入 0–90 分钟直播，常规时间约 8 秒。进球根据事件分钟逐步揭晓比分、球员与助攻，不提前展示冠军或决赛个人奖项。90 分钟平局才进入 30 分钟加时，按相同速率约 2.67 秒；120 分钟仍平才进入点球大战。双方轮流罚球，每次点击揭晓一脚；首五轮可提前结束，之后进入成对突然死亡。主罚顺序遍历本队球员后循环，点球不计入射手或助攻榜。终场后统一结算冠军与个人奖项。

联机新增 `fc_final_v5` 保存服务器开始时间、已揭晓点球脚数和完成状态。双方用相同种子、阵容与开始时间观看，使用期望脚数防止并发点击跳两脚；正常推进要等比赛时钟结束后完成。单人点球状态和开始时间保存在浏览器；刷新会按实际已过去时间恢复。后台标签页可能受浏览器计时节流，回到页面按真实时间追平。原有单人 Skip to end 仍直接结算；直播中禁用跳过按钮。

首次使用联机决赛需要执行 [最新合并 SQL](supabase/upgrade-all-v5.sql)，包含以前所有升级，具体步骤见 [操作说明](docs/online-setup.md)。比赛及点球结果由固定种子的客户端引擎重现，服务器负责时钟与操作进度，仍是朋友间原型，尚非完整服务端权威比赛引擎。双方都应刷新到同一版本。旧版已完成的单人赛季保留原结果，不重新改写冠军。

`tests/final-match.test.js` 核验 160 个种子的常规时间、加时、点球提前结束、突然死亡、进球统计和结果一致性；`tests/browser-final.mjs` 分别验证三条直播路径、8 秒时钟、逐脚点击及刷新恢复。数据库与双浏览器检查包括同时点击只推进一脚、相同赛果和升级重跑保留进度。

冠军页的金靴和助攻王分别独占一行。阵型菜单移除 3-5-2 与 3-4-1-2；内部保留旧阵型定义用于读取既有存档及历史联机结果，不清空原阵容。新增 4-3-3 进攻型：三前锋、一个前腰、两个中前卫、四后卫及门将。旧阵型存档可选择切换到当前菜单阵型。联机使用新增阵型前需再执行最新 `supabase/upgrade-all-v5.sql`，服务器按前腰与中前卫的正确位置重算能力。

## v6 球员扩充与原评级标记

新增 25 支精选球队年代、560 条球员版本；其中包含巴西 2014/2018/2022、曼联 2008/2011、巴萨 2006/2015、皇马 2024、拜仁 2001/2013/2020、国际米兰 2010、尤文图斯 2015 和巴黎 2020 等。球员名单是精选阵容，不声称全部官方报名均完整复核。新增球员中文名与整理身高在 `catalog-expansion.js`，缺失资料仍按既有稳定游戏值补全；头像维持剪影。

取消来源球队最多三名 S/S+ 的硬限制，恢复 2002 巴西、1970 巴西、1989 米兰、2009 巴萨等强队部分核心的高评级。巅峰 2006 巴萨罗纳尔迪尼奥为 99/S+，2002 巴西版本为 96/S；2002 卡福现为 99/S+。不同版本不一刀切，后场重评后 S+ 共 44 条记录（约 2.8%），S 为 334 条（约 21.5%）。2020 拜仁同时有 99 分诺伊尔和莱万。

阵容卡保留实际分数、姓名、厘米身高及位置，移除位置后面的等级字母；边框随最终能力改变。只要实际分数与初始值不同（包括同档位内变化及羁绊加分），右上角出现 `was S+` 等初始评级标记；鼠标提示也显示初始分数。恢复初始分数后标记消失，试位和正式入队一致。候选卡继续显示原始评级与初始能力。

SQL 生成同时输出 `setup-all.sql`，将初始化及全部升级放在一个事务内；数据库集成测试从空数据库执行此文件，并在已有赛果、点球进度后再次执行以检查幂等。`tests/browser-catalog.mjs` 检查新增球员、87/B 的 was S+ 标记、位置行与恢复原位置及手机排版。

## v7 后场与三人羁绊

`defense-ratings.js` 针对具体球队、具体年份重评后卫，不给同名球员所有版本统一加分，不修改前场原始评分。后场原来没有 S+，现在有 18 个 S+ 球员版本，覆盖中后卫及左右后卫；后场 S 版本共 188 个。示例：1966 博比·摩尔、1982 西雷阿、1989 巴雷西/马尔蒂尼、2002 卡福/皇马卡洛斯、2006 卡纳瓦罗/阿什利·科尔、2008 费迪南德、2010 麦孔、2013 拉姆、2017 拉莫斯/马塞洛、2019 范戴克等为 99。评分是游戏编辑判断，不是官方能力值；位置和年代扣分仍然有效。

BBC（C罗、贝尔、本泽马）、MSN（梅西、内马尔、苏亚雷斯）三人同时在首发 11 人内，各获 +5 分。荷兰三剑客（古力特、范巴斯滕、里杰卡尔德）各获初始能力的 5%，四舍五入为整数。例如 84 分 +4、90 分 +5。三人羁绊与双人羁绊取较高值，不相加；随后扣位置及年代影响，再将最终能力限制在 15–100。替补不激活三人组；双人搭档原有替补激活规则不变。激活三人组后面板优先显示三人组合，不重复列出其内部双人关系。

服务器私有三人组表和五参数评分函数从实际提交的前 11 个球员目录身份重新计算，不信任客户端的首发身份列表或评分。旧四参数函数保留作双人兼容入口，两个私有函数均禁止 anon/authenticated 直接调用。联机首次使用该版需再次执行 `supabase/setup-all.sql`；网页通过 `chemistry_version: 2` 检测旧库并提示升级。完整 SQL 可从头安装，也可在已有阵容/赛果/点球进度后重复执行。

`tests/defense-trios.test.js` 覆盖后场目标、三人首发/替补、固定与百分比加分、互斥叠加及 100 上限。数据库测试对 BBC、MSN、荷兰组合分别确认客户端与服务器同分，浏览器检查试位不正式激活、确认后显示金色三人组面板以及换到替补后失效。
